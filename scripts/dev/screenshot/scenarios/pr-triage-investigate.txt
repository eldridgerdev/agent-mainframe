# PR Triage — Investigate a review comment (read-only), offline fixture.
#
# Seeds a demo project + feature on this branch and a pr_review_cache row (a
# hit for this branch's PR) plus a *completed* pr_investigations row for one of
# its comments. `G` resolves straight to that PR and the pane shows the
# hand-written comments and the persisted investigation with no live comment
# fetch and no model call. Fully offline (git rev-parse only).
#
# Run with:
#   scripts/dev/screenshot/amf-capture.sh \
#     --scenario scripts/dev/screenshot/scenarios/pr-triage-investigate.txt \
#     --out-dir <dir>

run:printf '{"path":"%s","project_name":"pr-triage-investigate-demo","dry_run":false}\n' "$REPO_ROOT" > "$XDG_STATE_HOME/inv-project.json"
run:$AMF_BIN automation create-project --file "$XDG_STATE_HOME/inv-project.json"
wait:900
run:python3 scripts/dev/screenshot/seed-investigation-fixture.py "$XDG_CONFIG_HOME/amf/amf.db" "$REPO_ROOT"
wait:400

# Automation runs against the already-loaded TUI; restart it so the seeded
# project, feature, cache row, and investigation are read from the scratch DB.
run:tmux respawn-pane -k -t "$SESSION" "$AMF_BIN"
run:for i in {1..60}; do tmux capture-pane -p -t "$SESSION" > "$XDG_STATE_HOME/inv-pane.txt"; grep -q "pr-triage-investigate-demo" "$XDG_STATE_HOME/inv-pane.txt" && break; sleep 0.2; done
wait:6000

# Expand the demo project, land on its feature, open PR Triage.
key:l|wait:400
key:j|wait:400
key:G|wait:4000
note:PR Triage with the selected comment's completed read-only investigation shown in the right panel — the "Investigation (read-only)" section leads with a status / harness / time chip line ([complete] [Codex] [time]), then the answer in Markdown. This is what persists per pull request and reopens with the overlay.
shot:triage-investigation-detail

# Scroll the detail pane down to reveal the follow-up thread beneath the answer.
key:C-d|wait:250
key:C-d|wait:250
key:C-d|wait:250
key:C-d|wait:250
note:Scrolling the detail pane reveals the follow-up thread beneath the answer — "Follow-up 1: <question>" and its answer, from a second read-only run that re-used the prior answer as context (the Learning Mode `F` behaviour).
shot:investigation-followup-thread

# `a` opens the completed-investigation action menu. (`v` itself launches a
# fresh read-only run, so the scenario doesn't press it — it would spawn a real
# headless pass in CI; the seeded investigation stands in for a finished one.)
key:a|wait:800
note:The `a` action menu for a finished investigation — the operator picks what happens to the answer each time, with no fixed default: post an editable reply (prefilled from the answer), ask a follow-up, dismiss, or keep as a TODO. Fix and batch are not here: `f` and `B` act on the comment normally whether or not it carries an investigation.
shot:investigation-action-menu

# Choose "Ask a follow-up" (row 1) and type a question (do not submit — Tab
# would spawn a real read-only run; Esc cancels).
key:j|wait:200
key:Enter|wait:500
text:Is there a test that would catch it if that early return were dropped?|wait:500
note:"Ask a follow-up" opens an inline question editor. Submitting (Tab) re-runs the investigation read-only with the prior answer as context and appends the reply as a new turn in the thread.
shot:followup-question-editor
key:Escape|wait:400
