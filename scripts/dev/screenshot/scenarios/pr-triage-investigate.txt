# PR Triage — Investigate a review comment (read-only), offline fixture.
#
# Seeds a demo project + feature and a pr_review_cache row for a real open PR
# (#434 by default) plus a *completed* pr_investigations row for one of its
# comments. Opening that PR by number is a cache hit, so the pane shows the
# hand-written comments and the persisted investigation with no live comment
# fetch and no model call. One read-only `gh pr view` runs (in the seeder) to
# learn the PR head SHA.
#
# Run with:
#   scripts/dev/screenshot/amf-capture.sh \
#     --scenario scripts/dev/screenshot/scenarios/pr-triage-investigate.txt \
#     --out-dir <dir>

# The demo project must point at a real git repo so `gh` and PR resolution
# work; `.` would resolve against the running TUI's cwd (the scratch root).
run:printf '{"path":"%s","project_name":"pr-triage-investigate-demo","dry_run":false}\n' "$REPO_ROOT" > "$XDG_STATE_HOME/inv-project.json"
run:$AMF_BIN automation create-project --file "$XDG_STATE_HOME/inv-project.json"
wait:900
run:GH_CONFIG_DIR="$REAL_GH_CONFIG_DIR" python3 scripts/dev/screenshot/seed-investigation-fixture.py "$XDG_CONFIG_HOME/amf/amf.db" "$REPO_ROOT"
wait:400

# Automation runs against the already-loaded TUI; restart it so the seeded
# project, feature, cache row, and investigation are read from the scratch DB.
run:tmux respawn-pane -k -t "$SESSION" "$AMF_BIN"
run:for i in {1..60}; do tmux capture-pane -p -t "$SESSION" > "$XDG_STATE_HOME/inv-pane.txt"; grep -q "pr-triage-investigate-demo" "$XDG_STATE_HOME/inv-pane.txt" && break; sleep 0.2; done
wait:6000

# Expand the demo project and land on its feature.
key:l|wait:400
key:j|wait:400

# `G` on a branch with no PR of its own opens the repo's PR picker.
key:G|wait:3000
note:PR Triage's picker after `G` — the feature's branch has no PR of its own, so it lists the repository's open pull requests to choose from.
shot:pr-picker

# Choosing the PR opens PR Triage; the seeded pr_review_cache row is a hit.
key:Enter|wait:3000
note:PR Triage with the selected comment's completed read-only investigation shown in the right panel — the "Investigation (read-only)" section leads with a status / harness / time chip line ([complete] [Codex] [time]), then the answer in Markdown. This is what persists per PR and reopens with the overlay.
shot:triage-investigation-detail

# Scroll the detail pane down to reveal the follow-up thread beneath the answer.
key:C-d|wait:200
key:C-d|wait:200
key:C-d|wait:200
key:C-d|wait:200
note:Scrolling the detail pane reveals the follow-up thread beneath the answer — "Follow-up 1: <question>" and its answer, from a second read-only run that re-used the prior answer as context (the Learning Mode `F` behaviour).
shot:investigation-followup-thread

# `v` routes this comment to investigate rather than fix.
key:v|wait:500
note:Pressing `v` toggled this comment from fix to investigate — the list row now carries the `⌕` marker (see the footer legend). Default stays fix; `v` again returns to it, and the next `f` on this comment runs a read-only investigation instead of injecting a fix.
shot:routed-to-investigate

# `a` acts on the finished investigation.
key:a|wait:500
note:The `a` action menu for a finished investigation — the operator picks what happens to the answer each time: convert to fix, add to batch, post an editable reply, ask a follow-up, dismiss, or keep as a TODO.
shot:investigation-action-menu
key:Escape|wait:300
