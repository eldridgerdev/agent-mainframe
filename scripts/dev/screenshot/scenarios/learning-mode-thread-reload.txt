# learning-mode-thread-reload: a follow-up stays with the question it
# continues after the overlay is closed and reopened.
#
# Stored history reloads oldest-first, but a follow-up is asked *after*
# whatever else was asked in between — and the history pane takes a row's
# placement from the list while taking only its indentation from
# parent_qa_id. So a reopened history used to show the follow-up indented
# under an unrelated question. (docs/backlog/learning-mode-plan.md,
# Epic 6.)
#
# The order this drives — ask, ask something else, then follow up on the
# *first* one — is the only order that shows it: a follow-up on the most
# recent question is already adjacent to its parent either way.
#
# Needs a seeded project + feature and asks three real questions, so the
# harness must be authenticated:
#   ./amf-capture.sh --scenario scenarios/learning-mode-thread-reload.txt \
#       --seed <scratch>/seed-project.json \
#       --seed-feature <scratch>/seed-feature.json \
#       --geometry 160x44 --keep
#
# --keep on purpose: the scratch amf.db is the interesting artifact. The
# same stored history rendered by a pre-fix binary is the "before" frame,
# with no further questions asked.
