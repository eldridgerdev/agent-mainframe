# quick-plan-mode: visual proof of the Quick Plan feature (AMF_PLAN.md).
#
# Shows, in order:
#   1. 'Q' on an existing feature opening the Quick Plan interview — the
#      same brief screen full Plan mode uses, but titled "Quick Plan"
#      instead of "Plan Mode" (PlanInterviewMode::Quick's label).
#   2. The feature-creation wizard's Mode step, where the Plan field is now
#      a 3-way cycle (None / Quick Plan / Full Plan) instead of a checkbox.
#   3. The '?' help overlay showing the new 'Q' keybinding next to 'P'.
#
# Requires --seed quick-plan-seed-project.json and --seed-feature
# quick-plan-seed-feature.json (both committed alongside this scenario).
# Every `--seed`/`--seed-feature` used for a local `amf-capture.sh` run of
# this scenario MUST also be passed to `amf-publish-screenshots`/
# `publish-pages.sh` — the remote capture workflow starts from a blank
# scratch instance too. Forgetting this once (missing --seed/--seed-feature
# on the publish call) is exactly what previously made every 'j'/'Q'/typed
# keystroke below fall through to unrelated dashboard-level keybindings
# instead of driving this flow — every shot below now carries an
# expect:/expect_not: so that failure mode fails the run loudly instead of
# silently publishing the wrong screenshots again.
#
# quick-plan-seed-project.json points `path` at `__REPO_ROOT__` (this
# checkout) with `quick-plan-seed-feature.json` using `use_worktree: false`,
# so the seeded feature lives at the repo root with no worktree of its own.
# The feature-creation wizard's "n" step below assumes there is no OTHER
# worktree available to reuse, so it lands on the Branch (name) field
# directly rather than the Source picker -- true for a fresh single-ref CI
# checkout (`actions/checkout@v4` creates exactly one worktree: itself), but
# NOT necessarily true if you run this locally inside a checkout that is
# itself one of several `git worktree`s of the same parent repo (as this
# repository's own dev checkouts commonly are) -- `git worktree list` there
# will show every sibling worktree as "available", and the wizard opens on
# the Source picker instead. That is a local-environment quirk, not a scenario
# bug: to validate locally, seed against a disposable one-worktree scratch
# repo instead (`git init` a throwaway dir and point a local-only copy of
# quick-plan-seed-project.json's `path` at it) rather than `__REPO_ROOT__`.
#
# Deliberately aborts every interview/wizard before accepting or creating
# anything: accepting a Quick Plan interview runs a real headless AI round,
# which costs tokens and would make the capture slow and non-deterministic.
# Only the Brief step (no harness call yet) is shown.

note:The seeded dashboard shows one project and one feature with no plan yet, the starting state for every trigger below.
expect:quick-plan-demo

shot:dashboard-seeded

wait:300
note:Selecting the feature row is required before either plan-interview trigger, since the interview plans one feature's workdir.

shot:feature-selected
