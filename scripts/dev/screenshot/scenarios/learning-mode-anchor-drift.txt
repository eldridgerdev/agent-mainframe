# learning-mode-anchor-drift: a stored question's line range is checked
# against the code as it is now, every time the overlay opens
# (docs/backlog/learning-mode-followups-plan.md, "Anchor drift").
#
# A learning_qa row stores file_path + line_start/line_end. Editing the
# file afterwards used to leave every earlier entry pointing at whatever
# had since taken those line numbers, silently — and a stale anchor does
# not look stale, it looks like an answer that was always wrong. This
# scenario is the whole argument: ask a real question about lines 3-6,
# move that code down, reopen, and read what the entry says about itself.
#
# The `run:` steps are load-bearing rather than setup. Anchor drift only
# exists across a close/reopen with a file edit in between, so the edit
# has to happen mid-scenario; it edits the seeded repo directly, which is
# also how a real user's agent would have changed it.
#
# Needs a seeded project + feature at /tmp/amf-drift-demo and asks one
# real question, so the harness must be authenticated:
#   ./amf-capture.sh --scenario scenarios/learning-mode-anchor-drift.txt \
#       --seed /tmp/amf-drift-proj.json \
#       --seed-feature /tmp/amf-drift-feat.json \
#       --geometry 140x44
#
# 140x44 to match the rest of the Learning Mode captures: the drift
# sentence is sized to the pane, so this shows the two-row form.

wait:1500
shot:dashboard

# help overlay by itself; Escape starts browsing.

# not be looking at.
