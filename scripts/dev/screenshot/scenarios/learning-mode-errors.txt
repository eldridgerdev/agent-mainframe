# learning-mode-errors: the failure paths Learning Mode used to keep to
# itself. Every frame here is a message that previously either said only
# what failed, or said nothing at all.
#
# Seeded with a deliberately awkward NON-git project, so the repo listing
# comes from the fallback walk rather than `git ls-files`:
#
#   notes-app/
#     README.md            readable
#     main.py              readable
#     lib/store.py         readable
#     assets/icon.bin      binary (NUL bytes)
#     credentials.env      mode 000 -- listable, unreadable
#     vendor-cache/        mode 000 -- the walk cannot open it at all
#
# Build that project first (DEMO is wherever you want it; the seed JSON's
# `path` must point at it). Do NOT run as root -- the mode 000 entries are
# the whole point, and root reads them anyway:
#
#   mkdir -p "$DEMO"/{lib,assets,vendor-cache}
#   echo '# notes-app' > "$DEMO/README.md"
#   echo 'print("hi")'  > "$DEMO/main.py"
#   echo 'import json'  > "$DEMO/lib/store.py"
#   printf 'PK\x03\x04\x00\x00binary\x00\xff' > "$DEMO/assets/icon.bin"
#   echo 'inner' > "$DEMO/vendor-cache/inner.py"
#   echo 'API_TOKEN=x' > "$DEMO/credentials.env"
#   chmod 000 "$DEMO/credentials.env" "$DEMO/vendor-cache"
#
# The row counts in the j-presses below assume the file list AMF ends up
# with after it writes its own .claude/ hooks and skills into the project.
# If those change, recount against frame 003 rather than trusting them.
#
# Run with:
#   ./amf-capture.sh --scenario <scratch>/learning-mode-errors.txt \
#     --seed <scratch>/seed-project.json \
#     --seed-feature <scratch>/seed-feature.json \
#     --geometry 140x40
