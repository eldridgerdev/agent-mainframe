# PR Triage — stale-hunk note on a fix prompt (offline fixture).
#
# Proves the fix: PrComment::fix_prompt_with_note / combined_fix_prompt
# (src/app/pr_review/domain.rs) now warn the agent when another comment on
# the same file was already fixed (or is mid-fix) earlier in this triage
# session, since GitHub's cached diff_hunk/line reflect the file as it stood
# when the PR was fetched — not after that earlier fix.
#
# Offline for the comment content: seeds a demo project + feature and a
# pr_review_cache row keyed to PR #434's real head SHA (its actual content is
# irrelevant — only its number/head SHA are borrowed as a stable cache key,
# same trick pr-triage-investigate*.txt use). `G`/`g`/`#` reach the manual
# PR-number prompt regardless of whether the current branch auto-resolves to
# its own PR (`g` opens the picker from a live PR Triage view) or falls
# straight to the picker (no PR yet, where `g`/`#` both open the same
# prompt) — see the step comments below. Typing 434 there resolves it by
# number (one read-only `gh pr view`) and hits the seeded cache row — no
# live comment fetch, no model call. The scenario opens the fix-confirm
# dialog to inspect the assembled prompt but always cancels (`Esc`) rather
# than injecting, so no agent session is ever spawned.
#
# Run with:
#   scripts/dev/screenshot/amf-capture.sh \
#     --scenario scripts/dev/screenshot/scenarios/pr-triage-stale-hunk-note.txt \
#     --out-dir <dir>

run:printf '{"path":"%s","project_name":"pr-triage-stale-hunk-demo","dry_run":false}\n' "$REPO_ROOT" > "$XDG_STATE_HOME/stale-project.json"
run:$AMF_BIN automation create-project --file "$XDG_STATE_HOME/stale-project.json"
wait:900
# `gh` in a `run:` step needs the real config dir pointed at explicitly — the
# driver only pins GH_CONFIG_DIR for the tmux instance, not this shell.
run:GH_CONFIG_DIR="${GH_CONFIG_DIR:-$HOME/.config/gh}" python3 scripts/dev/screenshot/seed-stale-hunk-fixture.py "$XDG_CONFIG_HOME/amf/amf.db" "$REPO_ROOT" 434
wait:400

# Automation ran against the already-loaded TUI; restart it so the seeded
# project, feature, cache row, and triage row are read from the scratch DB.
run:tmux respawn-pane -k -t "$SESSION" "$AMF_BIN"
run:for i in {1..60}; do tmux capture-pane -p -t "$SESSION" > "$XDG_STATE_HOME/stale-pane.txt"; grep -q "pr-triage-stale-hunk-demo" "$XDG_STATE_HOME/stale-pane.txt" && break; sleep 0.2; done
wait:6000

# Expand the demo project and land on its feature.
key:l|wait:400
key:j|wait:400

# `G` resolves the current branch's own PR if one exists, otherwise falls to
# the picker — either way, `g` then reaches the manual number prompt: from a
# live PR Triage view it opens the picker (whose own `g`/`#` both open the
# prompt), and from the picker it opens the prompt directly. So this sequence
# lands on the prompt regardless of which path `G` took, and the following
# `#` is a harmless no-op if the prompt is already open (non-digits are
# ignored). Typing 434 there opens the exact seeded PR regardless of how many
# open PRs the real repo currently has (and in whatever order).
key:G|wait:4000
key:g|wait:800
key:#|wait:400
text:434|wait:200
key:Enter|wait:4000

expect:[~]
expect:Nit: this can just delegate to the new helper
note:PR Triage open on the seeded PR: three comments, the first ("Nit: this can just delegate...") already marked `[~]` Fixing — simulating a fix already sent off earlier in this triage session. The second and third comments are still untriaged.
shot:triage-comment-list

# Move to the second comment: same file (src/app/pr_review/domain.rs) as the
# already-Fixing one, but not yet triaged.
key:j|wait:400
expect:Should this note also mention the combined-batch case
note:Selection moved to the second comment — same file as the one already marked Fixing, still untriaged.
shot:triage-second-comment-selected

# `f` opens the fix-target picker (first fix of this pane visit).
key:f|wait:600
note:First `f` of this pane visit opens the fix-target picker before showing the prompt. Accepting the highlighted (dedicated) row and its default session name gets straight to the fix-confirm dialog.
shot:fix-target-picker
key:Enter|wait:400
key:Enter|wait:800

# Split across two `expect:` lines rather than the note's full sentence: the
# dialog's fixed width wraps the note text, so a substring spanning a wrap
# point would never match the flattened capture even though it renders fine.
expect:was already addressed earlier in this triage
expect:may no longer match the file's current content
note:The fix-confirm dialog for the second comment now carries the new staleness note: another comment on this same file (src/app/pr_review/domain.rs) was already marked Fixing earlier in this triage session, so the file:line pointer and diff hunk shown may no longer match the file's current content.
shot:fix-confirm-stale-hunk-note

# Cancel without injecting — this only inspects the assembled prompt.
key:Escape|wait:400

# Move to the third comment: a different file, untouched by anything else in
# this session. The harness pick is already resolved for this pane visit, so
# `f` goes straight to the confirm dialog.
key:j|wait:400
key:f|wait:800

expect_not:was already addressed earlier in this triage
note:The third comment is on a different, untouched file (src/app/pr_review/integration.rs) — no sibling comment on it has been fixed, so its fix-confirm dialog carries no staleness note. Contrast with the previous shot.
shot:fix-confirm-different-file-no-note

key:Escape|wait:400
